2. Installation

Choose one method. If you already have Python, Option B (pip) is recommended — it doesn't require admin rights.

Option A — winget (requires admin)

Open PowerShell as Administrator and run:

winget install Microsoft.AzureCLI

Option B — pip (no admin required)

pip install azure-cli
Important: pip installs to the Roaming folder

When installed via pip, the az command is placed in:
C:\Users\<you>\AppData\Roaming\Python\Python3xx\Scripts\
This folder is typically not on your PATH. See Section 3 to fix this.

Option C — MSI installer

Download the installer from https://aka.ms/installazurecliwindows and run it. This adds az to PATH automatically.

3. Fix PATH (pip installs only)

Why this is needed

Python's pip installs user packages to the Roaming AppData folder (%APPDATA%\Python\...), but only the Local AppData scripts folder (%LOCALAPPDATA%\Python\...) is typically on PATH. So az is installed but not found by your terminal.

Check if az is reachable

where.exe az

If it says "Could not find files", fix the PATH:

Add the Roaming scripts folder to your user PATH

Run in PowerShell (no admin required):

# Adjust the Python version if yours differs (e.g. Python312)
$roamingScripts = "$env:APPDATA\Python\Python313\Scripts"
$currentPath = [Environment]::GetEnvironmentVariable("Path", "User")

if ($currentPath -notlike "*$roamingScripts*") {
    [Environment]::SetEnvironmentVariable("Path", "$currentPath;$roamingScripts", "User")
    Write-Host "Added to PATH. Restart your terminal."
} else {
    Write-Host "Already in PATH."
}
Restart your terminal

PATH changes only take effect in new terminal sessions. Close and reopen PowerShell/CMD after running the above.

4. Login & MFA for Write Operations

Critical: Our Azure tenant requires MFA for resource management

A standard az login may authenticate you for read operations (listing resources, querying pipeline runs) but fail on writes (creating/updating pipelines, triggers, etc.) with this error:

ERROR: Unauthorized — RequestDisallowedByAzure
"You are receiving this error because you tried to create, update
or delete Azure resources without authenticating through MFA."

Standard login (sufficient for read-only work)

az login

Opens a browser for sign-in. Good enough for queries and monitoring.

MFA-capable login (required for write operations)

Use the device code flow, which forces a fresh interactive authentication that satisfies MFA:

# First, clear any cached tokens
az logout

# Then login with device code flow + explicit tenant
az login --tenant 24d3c3a1-4634-424a-a6d2-f30aace549d1 --use-device-code
1
The CLI will display a code and a URL. Open the URL in your browser.
2
Enter the code, sign in with your Pilgrim's Europe account, and complete the MFA challenge (Authenticator app, SMS, etc.).
3
Return to the terminal — you should see "You have logged in" and your subscription listed.
When to re-authenticate

MFA tokens expire. If write operations start failing with the MFA error after a period of inactivity, repeat the logout → device-code login flow above.

Query a pipeline run (confirms read access)

All working?

If the above returns a JSON list of pipelines, your CLI is fully configured.

7. Troubleshooting

ProblemCauseFix
az: command not found The Roaming Python Scripts folder is not on PATH See Section 3. After fixing, restart your terminal.
RequestDisallowedByAzure — MFA error on write operations CLI session doesn't have an MFA-satisfied token Run az logout then az login --tenant 24d3c3a1-... --use-device-code. See Section 4.
az commands produce empty output in Git Bash Git Bash doesn't always capture az.bat stdout correctly Use PowerShell or CMD instead. Or run via Python: subprocess.run(['az.bat', ...], shell=True)
'&&' is not a valid statement separator in PowerShell PowerShell uses ; not && Run commands separately, or use ; to chain them.
The command line is too long when passing JSON body Windows command line length limit (~8191 chars) Save JSON to a file and use --body @filepath.json
%1 is not a valid Win32 application Trying to execute az (the Python script) directly instead of az.bat Always use az.bat when calling from Python subprocess, or ensure the .bat extension is in PATHEXT.
Please run 'az login' No active session / token expired Run az login (reads) or the device-code flow (writes).
datafactory commands not recognized Extension not installed az extension add --name datafactory

Common ADF CLI commands

# List all pipelines
az datafactory pipeline list --resource-group ETL --factory-name Core-Factory --output table

# Show a specific pipeline run
az datafactory pipeline-run show --resource-group ETL --factory-name Core-Factory --run-id "<run-id>"

# Query activity runs within a pipeline run
az datafactory activity-run query-by-pipeline-run \
  --resource-group ETL --factory-name Core-Factory \
  --run-id "<run-id>" \
  --last-updated-after "2026-10-01T00:00:00Z" \
  --last-updated-before "2026-10-13T00:00:00Z"

# Trigger a pipeline manually
az datafactory pipeline create-run --resource-group ETL --factory-name Core-Factory --name "Arolink_production_yield"
